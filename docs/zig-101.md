# Zig 101, taught through `core/`

A walkthrough of the Zig library in this repo, written for reading alongside the source.

Every claim below was checked against the committed files. Line references are `file:line`
against `core/src/*` on `dev` at 0.4.1. Where I reasoned rather than measured, I say so. The
design records in `docs/decisions/` hold the decisions; the code is the truth where the two
disagree, and I flag it.

---

## 1. Orientation

`core/` is a Zig library with no external Zig dependencies (`core/build.zig.zon`, empty
`dependencies`; decision 0001). It owns audio memory, capture, mixing, playback, the write path,
span reads, summary statistics, peak bins, WAV reading and writing with markers, the scratch
writer and its RAM cache, and the memory query. Python creates handles and reads numbers; the
Qt UI is the only Python left (decision 0002; `native.py:4-10`).

## 2. Zig concepts, through this code

### 2.1 A file is a type

`Ring.zig:19`:

```zig
const Ring = @This();
```

Then the next lines are struct fields at file scope:

```zig
allocator: std.mem.Allocator,
frames: []f32, // storage_frames * channels, interleaved, one allocation, forever
capacity: u64, // in frames — the READABLE window; unchanged by the guard band below
```
`Ring.zig:21`

The file is the struct. `@This()` names the enclosing scope, which at file scope is the file's
own type. `@import("Ring.zig")` returns that type, so `const Ring = @import("Ring.zig")` gives
you a type you can call `Ring.init(...)` on. `Summary.zig:10` does the same, and so do
`Capture.zig:10`, `Mixer.zig:21`, `Playback.zig:13`, `Scratch.zig:42`, `Checkout.zig:21`,
`ErrorSlot.zig:5`, `FakeBackend.zig:8`, `WasapiBackend.zig:14`.

Coming from Python: there is no `class Ring:` line and no module-versus-class distinction. One
type per file, named by the filename. That is why the files above are capitalized and `wav.zig`,
`abi.zig`, `peaks.zig`, `mem.zig`, `convert.zig`, `wasapi.zig` are not: the lowercase ones are
namespaces of functions, not types. One exception: `Backend.zig` is capitalized but has no
`@This()`; it is a namespace holding three types, `Backend`, `Stream`, `RenderStream`
(`Backend.zig:19`, `:49`, `:85`).

### 2.2 Allocators are parameters

```zig
pub fn init(allocator: std.mem.Allocator, config: Config) !Ring {
```
`Ring.zig:59`

There is no global heap. `std.mem.Allocator` is an interface value the caller supplies. Tests
pass `std.testing.allocator`; the ABI passes one shared `std.heap.smp_allocator`
(`abi.zig:26`, rationale at `:20-25`). The struct stores it so `deinit` can free with the same
allocator that allocated.

The `!Ring` return type is an error union: either a `Ring` or an error. The error set is
inferred from the `try`s in the body. `abi.zig:184-191` pins that `Ring.init`'s inferred set is
exactly `InvalidArgument` and `OutOfMemory`, by switching on it exhaustively.

The audio threads never allocate. `Mixer` allocates its staging rings in `init` and works in two
fixed arrays after that (`Mixer.zig:7-9`, `:41-45`). `Playback` allocates a clip only in `bind`,
on the control thread (`Playback.zig:1-6`). `Scratch` allocates only for a `.load` job, and only
the clip (`Scratch.zig:12-16`).

### 2.3 `errdefer`, and the multi-`errdefer` init

```zig
const frames = try allocator.alloc(f32, storage_frames * config.channels);
errdefer allocator.free(frames); // runs only if a later `try` fails
@memset(frames, 0);
```
`Ring.zig:78`

`defer` runs when the scope exits. `errdefer` runs only when the scope exits with an error.
Pair every fallible allocation with its own `errdefer` immediately after it, and a failure
halfway through construction unwinds exactly the allocations that succeeded. No `goto cleanup`
ladder, no leak.

`Summary.init` is the full version, five allocations, five `errdefer`s (`Summary.zig:29-38`):

```zig
const min = try allocator.alloc(f32, n_slots * channels);
errdefer allocator.free(min);
const max = try allocator.alloc(f32, n_slots * channels);
errdefer allocator.free(max);
```

`Ring.init` keeps the pattern even where it is currently inert, and says so (`Ring.zig:87-92`).

Three more shapes appear in phase 2. An `errdefer` over a progress counter, so only the stages
that were built get torn down (`Mixer.zig:76-78`, `:105-108`). An `errdefer` that clears a flag
when a thread spawn fails (`Capture.zig:94`, `Mixer.zig:104`, `Playback.zig:168`). An
`errdefer` that closes a file (`wav.zig:132`).

`deinit` ends with a poison:

```zig
self.* = undefined; // poison: use-after-deinit becomes loud in Debug
```
`Ring.zig:111`, and the same in `Summary.zig:66` and `Mixer.zig:93`

In Debug, `undefined` is written as the byte pattern `0xaa`. Use-after-free reads garbage
loudly instead of reading plausible stale data quietly.

### 2.4 Error sets inside, status codes at the boundary

```zig
pub const ReadError = error{ Overwritten, OutOfRange };
```
`Ring.zig:48`

An error set is a closed enum of error tags. `ReadError!void` means "void, or one of those
two". Callers must handle it: `try`, `catch`, or an exhaustive `switch`. Two sets join with
`||` (`wav.zig:122`, `:220`).

Error unions cannot cross a C ABI. So the shim converts:

```zig
export fn fb_ring_read(ring: *Ring, abs_start: u64, n_frames: usize, out: [*]f32) FbStatus {
    ring.read(abs_start, out[0 .. n_frames * ring.channels]) catch |err| return switch (err) {
        error.Overwritten => .overwritten,
        error.OutOfRange => .out_of_range,
    };
    return .ok;
}
```
`abi.zig:266`

That `switch` is exhaustive over `ReadError`. Add a third error variant to `Ring.read` and this
file stops compiling. That is the point: the C boundary cannot silently forget a case. The same
shape covers `PeakBinsError` (`abi.zig:285-288`) and `ringCreate` (`:188-191`). Where the set
is open, the map has an `else`: `wavStatus` (`abi.zig:330-336`), `checkoutStatus`
(`:716-724`).

`FbStatus` is `enum(c_int)` (`abi.zig:28-35`) so the numeric values are the C header's values.
It has six: `out_of_memory = 5` arrived with the footprint work (`flashback_core.h:11-18`,
decision 0010).

### 2.5 Atomics and memory ordering

Five orderings appear, and each buys something specific.

**`.release`, the publish.** `Ring.write`:

```zig
self.summary.update(chunk, g, tw);
// The release-store PUBLISHES this chunk: everything written
// above becomes visible to any reader that acquire-loads a
// value >= tw + chunk_frames.
self.total_written.store(tw + chunk_frames, .release);
```
`Ring.zig:250`

A release store guarantees that every memory write the thread performed before it is visible
to any thread that later acquire-loads that value. The audio data lands first, the counter
second, and no compiler or CPU may move the data writes after the counter store.

**`.acquire`, the observe.** `Ring.read`:

```zig
const t1 = self.total_written.load(.acquire);
```
`Ring.zig:299`

An acquire load guarantees that everything the writer did before its matching release store is
visible to operations after this load. Pair one with the other and you get an ordered handoff,
without a lock.

**`.monotonic`, atomicity only.**

```zig
const g = self.gain.load(.monotonic);
...
const tw = self.total_written.load(.monotonic);
```
`Ring.zig:203`, `Ring.zig:225`

The writer reads its own counter. While a writer is registered nobody else stores it: the
control thread that spawned the writer stores `writer_active` true before the spawn and false
after the join (`Ring.zig:121-130`; `Capture.zig:88-94`, `:104-109`; `Mixer.zig:100-104`,
`:128-131`; decision 0006). `flush` checks that flag and, when a writer is registered, hands
the reset to the writer through `flush_pending` (`Ring.zig:131-137`); the writer drains it on
its own thread (`:181-186`). Only with no writer registered does `flushNow` store from the
control thread (`:157`). Gain is a single `f32` with no dependent data, so a torn or stale read
is impossible and a one-block delay is harmless. `.monotonic` costs nothing on x86 and avoids a
barrier on ARM.

**`.acq_rel`, both at once.** `Summary` bumps its generation to odd before writing a slot and
to even after, and the pre-bump is `.acq_rel` so the slot writes cannot hoist above it
(`Summary.zig:74-79`, `:108-113`). `Playback.run` consumes the `reopen` flag with
`swap(false, .acq_rel)` (`Playback.zig:281`).

**`.seq_cst`, the Dekker handshake.** `Playback.bind` and `Playback.fill` each store one flag
and then read the other's (`playing` and `in_copy`), and that only works when both stores are
globally ordered (`Playback.zig:129-135`, `:216-218`). It is the one place the strongest
ordering is needed, and the comment says why.

The code is honest about what this does not buy. From `Ring.zig:329-344`:

```
// (Formal-memory-model footnote, resolved: Zig 0.16 exposes no
// user-callable fence — `@fence` is an invalid builtin, ...
// An acquire load only orders operations AFTER it in
// program order — it does not order the copy ABOVE it relative
// to itself. On x86-64 ... TSO makes that a non-issue ...
```

Read that again when reviewing. The seqlock's second load is supposed to be ordered after the
copy, and Zig 0.16 gives no way to state that directly. On x86 the hardware does it. On ARM the
argument is empirical, not formal. `Summary.zig:186-190` restates the same gap for its own
seqlock. That is an accepted, documented limit, not an oversight.

### 2.6 Exhaustive `switch` on enums

```zig
pub fn bytesPerSample(self: Subtype) u8 {
    return switch (self) {
        .float32 => 4,
        .pcm_24 => 3,
        .pcm_16 => 2,
    };
}
```
`wav.zig:63`

No `else` branch. Add `pcm_32` to the enum and this switch is a compile error, as is
`formatTag` below it (`wav.zig:70-75`), the dispatch in `encodeSamples` (`:330-331`), and the
one in `decodeSamples` (`:259-274`). Four compile errors that name the four places a new format
needs a decision. `parseFmt`'s tag switch has an `else`, on purpose: a file can carry any tag
(`wav.zig:186-194`).

Coming from Python: this is the opposite of a dict lookup with a default. The absence of a
default is the feature. Use `else` only when you genuinely mean "and anything else".

The enum is explicitly backed by `u8` (`wav.zig:56`) because its values are wire values; the C
ABI passes 0/1/2. An unbacked enum's tag values are not guaranteed stable across compiler
versions. `Checkout.WriteState` (`Checkout.zig:23-25`), `Backend.Kind` (`Backend.zig:8`) and
`convert.SampleTag` (`convert.zig:5`) are backed for the same reason.

### 2.7 Slices, many-item pointers, sentinel pointers

Zig distinguishes three pointer-ish things. Internally, everything is a slice:

```zig
pub fn write(self: *Ring, interleaved: []const f32) void {
```
`Ring.zig:196`

`[]const f32` is a pointer and a length. Indexing is bounds-checked in Debug and ReleaseSafe.

C has no such type, so the boundary uses the other two:

```zig
export fn fb_ring_write(ring: *Ring, frames: [*]const f32, n_frames: usize) void {
    ring.write(frames[0 .. n_frames * ring.channels]);
}
```
`abi.zig:218`

`[*]const f32` is a many-item pointer: an address with no length, exactly C's `const float*`.
The shim rebuilds a slice from pointer plus caller-supplied count. The length contract now
belongs to the caller, and Zig cannot check it. The ABI test says so plainly at `abi.zig:45-47`.
Where the host sizes a buffer from an earlier call, the export takes an `out_len` and checks it
against its own view (`abi.zig:345-360`, `:362-375`, `:840-858`).

For strings, the length lives in the data:

```zig
export fn fb_wav_write(path: [*:0]const u8, ...) FbStatus {
    ...
    wav.writeFile(std.mem.span(path), ...
```
`abi.zig:300`, `abi.zig:319`

`[*:0]const u8` is a sentinel-terminated pointer, C's `char*`. `std.mem.span` scans for the
zero and returns a proper slice. The sentinel is part of the type, so you cannot pass a
non-terminated pointer here by accident. Every path-taking export uses it (`abi.zig:338`,
`:353`, `:659`, `:761`, `:881`), and `fb_capture_last_error` hands a `[:0]const u8` back the
other way (`abi.zig:609-611`; `ErrorSlot.zig:35-39`).

One more pointer shape: `[*]align(1) const f32`. WASAPI promises no alignment for packet bytes,
so `convert.zig:93-96` reads through pointers that say so, and the compiler emits unaligned
loads instead of trusting luck.

### 2.8 `export fn` and unmangled symbols

```zig
export fn fb_ring_create(rate: u32, channels: u16, seconds: f64, status: ?*FbStatus) ?*Ring {
```
`abi.zig:203`

`export fn` gives the function the C calling convention and an unmangled symbol name; the DLL
exports literally `fb_ring_create`. `pub fn` would not; it would only be visible to other Zig
code.

`?*Ring` is an optional pointer. In Zig, a plain `*Ring` can never be null; only `?*Ring` can.
On the C side both are just a pointer, and the header declares `FbRing *`
(`flashback_core.h:36`); the nullability lives in the Zig type and in the documented contract,
not in the C signature. `status` is a nullable out-pointer: pass NULL and you get a plain
null-or-pointer answer, pass a `FbStatus*` and you learn whether the failure was
`invalid_arg` or `out_of_memory` (`abi.zig:170-205`; issue #41).

Seven exports now return optional pointers: `fb_capture_create` (`abi.zig:580`),
`fb_mixer_create` (`:613`), `fb_playback_create` (`:659`), `fb_scratch_create` (`:726`),
`fb_checkout_create` (`:761`), `fb_checkout_slice` (`:773`), `fb_checkout_open` (`:787`).
Every other export takes a non-optional handle. A C caller that passes NULL to
`fb_ring_destroy` has broken the contract, and nothing in the shim checks it
(`abi.zig:213-216`).

Structs that cross the boundary are `extern struct`, and their layout is pinned by
`@sizeOf` and `@offsetOf` tests so a field reorder cannot silently shift the ctypes mirror
(`abi.zig:1345-1381`, `mem.zig:78-81`).

### 2.9 `comptime`

An assert that runs at compile time:

```zig
comptime {
    // FLOAT32's memcpy path writes host-endian bits as file bytes.
    // Every supported target is little-endian; make that loud, not lucky.
    std.debug.assert(builtin.target.cpu.arch.endian() == .little);
}
```
`wav.zig:10`

Cross-compile to a big-endian target and the build fails with a clear message, instead of
producing byte-swapped WAV files. The FLOAT32 path is a raw `@memcpy` of f32 bits
(`wav.zig:332-335` to encode, `:261` to decode), so this assert is what makes that shortcut
legitimate.

A force-reference that changes what gets emitted:

```zig
comptime {
    _ = abi;
}
```
`root.zig:60`

Zig's semantic analysis is lazy. Declarations nobody references are never analyzed, and code
that is never analyzed emits no symbols. `_ = abi;` references the module, which forces its
declarations to be analyzed, which is what puts the `export fn` symbols into the DLL.

Phase 2 added four more uses, all real:

- OS-gated imports. `root.zig:30-31` imports `wasapi.zig` and `WasapiBackend.zig` only when
  `builtin.os.tag == .windows`, else an empty `struct {}`. The Linux CI leg never analyzes a
  COM declaration. `abi.zig:549-552` picks the native backend the same way and `:560` picks the
  `FbProcess` type. `mem.zig:12-18` switches on the OS tag; only the referenced branch links,
  which is why the `kernel32` extern lives there and not in `wasapi.zig` (`mem.zig:36-39`).
- A GUID parsed at compile time. `wasapi.zig:19-40` turns a GUID string into the struct COM
  wants, with no runtime cost and a compile error for a malformed literal.
- Predicates as `comptime` parameters. Test waits take `comptime pred: fn (*Capture) bool`
  (`Capture.zig:45`, `Mixer.zig:251`, `Playback.zig:50`), so the wait loop is specialised per
  condition and no function pointer is stored.
- Format strings. `ErrorSlot.set` takes `comptime fmt` (`ErrorSlot.zig:23`), and
  `Playback.ramp(comptime n: usize)` builds a ramp table at compile time (`Playback.zig:314`).

Channels and sample rate stay runtime values (`Ring.zig:39-46`). The stack scratch sizes are
comptime constants (`Mixer.zig:44-45`, `Playback.zig:40`, `Summary.zig:242-243`,
`WasapiBackend.zig:57-61`).

### 2.10 `defer` ordering is LIFO, and it bit this codebase

Deferred statements run in reverse declaration order. That is not a detail. It caused a real
deadlock during construction, and the fix is commented in place:

```zig
// Defers run LIFO: stop must be signaled FIRST (declared LAST) so
// both joins below actually observe it and return. Declaring the
// signal before the joins (join-then-signal in source order, so
// signal-then-join in LIFO execution) deadlocked during development:
// flusher.join() ran before stop.store(true, ...) and waited forever
// on a thread whose loop condition could never go false.
defer writer.join();
defer flusher.join();
defer stop.store(true, .monotonic);
```
`Ring.zig:1049`

Read the three lines bottom-up to get execution order: signal stop, join flusher, join writer.
The cost was about three minutes of hang locally and a CI runner that burned 68 minutes before
a later push cancelled it. Three competing hypotheses were raised and all three were wrong; the
cause was defer order.

It recurred twice in phase 2. A parked scratch write must be unparked by the last registered
defer, so it runs before the destroy and the stop that would otherwise wait on it forever; a
combined defer hung the suite (`abi.zig:1115-1128`). And a worker must be stopped before its
ring is freed, so `defer stop` comes after `defer deinit` in source (`Capture.zig:431-434`,
`Scratch.zig:1053-1060`). `Mixer.start` relies on the same order for its `errdefer`s
(`Mixer.zig:105-108`).

The rule: when defers depend on each other, read them bottom-up.

### 2.11 Testing: leak detection and reachability

Tests live in the file they test, in `test "name" { ... }` blocks. They compile only in a test
build.

```zig
var ring = try Ring.init(std.testing.allocator, .{ ... });
defer ring.deinit();
```
`Ring.zig:512`

`std.testing.allocator` tracks every allocation. If a test ends with anything outstanding, the
test fails and prints the allocation's stack trace. Every test in this repo that constructs a
`Ring`, a `Summary`, a `Mixer` or a `Checkout` is therefore also a leak test, for free. Forget
the `defer ring.deinit()` and the suite goes red. Some tests pin a leak on purpose: an
idempotent `load` (`Checkout.zig:333`), and `abi.zig:1249-1257` runs a `FailingAllocator` over
`std.testing.allocator` so a failed `init` must free what it got.

Reachability is the sharper lesson. From `root.zig:33-39`:

```zig
// A `pub const` import alone is not enough: Zig's lazy Sema only analyzes
// declarations that are actually used, so an unreferenced `Ring` re-export
// would leave its `test` blocks (and any compile errors inside them)
// undiscovered — a build could report green having never looked at
// Ring.zig at all.
```

```zig
test {
    std.testing.refAllDecls(@This());
}
```
`root.zig:49`

And the constraint that comes with it (`root.zig:41-48`): `refAllDecls` is not recursive. It
walks exactly one level of pub decls; 0.16 has no `refAllDeclsRecursive`.

**The operative rule: every new `core/src/*.zig` must get its own
`pub const X = @import("X.zig");` line in `root.zig`, or its tests never run and the suite
still reports success.** `root.zig:7-22` lists sixteen; `:30-31` the two Windows-only files.
`FakeBackend.zig` is analyzed through the same list and exports nothing (`FakeBackend.zig:2-5`).
This is the single most important thing to know before adding a file to this library.

Threaded tests follow two more rules. Every temp path comes from `test_util.tmpPath`
(`test_util.zig:10`) or `wav.tmpWritePath` (`wav.zig:602-604`), under `.zig-cache/tmp/`, so a
test never writes into the build directory or a path that exists on one machine only. And the
`FakeBackend.Hold` union parks a worker inside `open` or before packet k until `release`
(`FakeBackend.zig:10-24`), so a test can put a thread exactly where the race is instead of
hoping for it.

One nuance I reasoned rather than measured: the `test` block is not compiled at all in the
library build. So for `zig build` (the DLL), `comptime { _ = abi; }` is not belt-and-braces; it
is the only thing forcing `abi.zig`'s analysis, and therefore the only thing emitting the
exports. Nothing in the repo inspects the export table to confirm it.

## 3. The design decisions, and how they were reached

Sources: the code, and `docs/decisions/0001` to `0011`.

### 3.1 `total_written` is the single source of truth

**Decision.** One atomic counter of frames ever written. There is no stored write position and
no stored read position. The writer derives its slot as `total_written % storage_frames`
(`Ring.zig:226`). Readers address by absolute frame index and never look past `total_written`.

**What it buys.** Publishing is one store (`Ring.zig:256`). There is no pair of counters that
can disagree. Two atomic bools sit next to the counter now, `writer_active` and `flush_pending`
(`Ring.zig:35-36`), but neither is a position; `total_written` is still the only one
(`Ring.zig:7`, `:142-143`).

**Rejected.** A claim-then-publish two-counter writer, considered as the fix for a tearing bug
and rejected because it would have broken this invariant. The guard band (below) was chosen
instead precisely because it adds no atomic position.

**Flush is two paths, not one store.** With a writer registered, `flush` sets `flush_pending`
and returns (`Ring.zig:131-134`); the writer drains it at the top of its loop, while idle, and
after the join (`Ring.zig:181-186`, `:202`; `Capture.zig:144`, `:165`, `:109`;
`Mixer.zig:184`, `:131`). With no writer registered, `flushNow` runs at once: poison the
summary, store 0, memset (`Ring.zig:146-159`). Issue #20 was the version where a writer that
loaded `tw` before a flush still published `tw + n` after it, undoing the flush; ownership of
the flag is what closed it (decision 0006).

**Consequence.** Everything stale past `total_written` is unreachable, so `flush` does not need
to zero memory for correctness (`Ring.zig:142-145`). It zeroes anyway, bounded and lock-free,
about 50 ms for a 345 MB ring (`Ring.zig:161-164`), because the zero-copy view is still read by
tests (`native.py:8-10`).

### 3.2 The seqlock protocol

```zig
const t1 = self.total_written.load(.acquire);
if (abs_start + n > t1) return error.OutOfRange; // span not written yet
if (t1 - abs_start > self.capacity) return error.Overwritten; // already lapped
... copy ...
const t2 = self.total_written.load(.acquire);
if (t2 >= abs_start + n and t2 - abs_start <= self.capacity) return;
```
`Ring.zig:299` to `346`, condensed

Copy first, validate after. Three attempts, then `error.Overwritten` (`Ring.zig:297-298`,
`:348`).

**What it guarantees.** A read that returns `ok` was not lapped during the copy. Readers never
block the writer.

**What it does not guarantee.** Progress. A reader losing every race gets an error, not data.
For a 300-second ring that is effectively never; the retry is insurance.

The `t2 >= abs_start + n` clause is checked first and is not redundant with the `t1` check.
`flush` can move `total_written` backwards to zero mid-read. Without that clause,
`t2 - abs_start` underflows an unsigned integer, which is illegal behavior and traps in Debug
and ReleaseSafe: a process abort inside a DAW. The full rationale is in place at
`Ring.zig:318-327`. That bug was found by review, not by tests. The test that now covers it
asserts only "never traps, and the result is `ok` or a documented `ReadError`"
(`Ring.zig:990-1071`).

The same protocol appears twice more. `Ring.peakBins` reads the ring in place through it and
verifies only the old end of the span (`Ring.zig:383-395`, `:448-455`; section 3.10).
`Summary.seqRead` wraps a caller-supplied read in a generation check with four bounded
attempts (`Summary.zig:148-159`; section 3.5).

### 3.3 The guard band

This is the subtlest decision in the codebase. Read `Ring.zig:263` to `292` in full.

**The hole.** `write` copies a chunk into physical slots before it publishes. Those slots
previously held frames one lap back. A reader can be accepted by the validity check, copy from
slots the in-flight write has already overwritten, and then observe `t2 == t1`, zero apparent
writer progress, because nothing was published yet. It returns success with torn data.

Note the shape of the failure: not "rare", but invisible. The seqlock's own check cannot see
it, because the check is on a counter that has not moved.

**The fix.** Allocate more than the readable window.

```zig
const storage_frames: u64 = capacity + max_write_frames;
```
`Ring.zig:77`

with

```zig
pub const max_write_frames: u64 = 4096;
```
`Ring.zig:57`

`capacity`, the readable window, is unchanged, and both validity checks still test against
it. Only the physical size and the modulo arithmetic use `storage_frames`.

**The argument** (`Ring.zig:278-286`): with `P = storage_frames`, `C = capacity`,
`M = max_write_frames`, `P = C + M`, a writer publishing at `t` and about to write `b <= M`
frames will occupy the slots that held frames `[t-P, t+b-P)`. An accepted read satisfies
`abs_start >= t - C = t - P + M >= t + b - P`. So the reader's span and the writer's in-flight
block are disjoint by construction, not by probability.

**The rejected alternative, and why.** The first ruling shrank the readable window instead:
`readable = capacity - max_write_frames`. Same disjointness, no extra memory. It was reversed
after checking the consumer (`Ring.zig:72-76`). Python's `get_latest` clamps a request to
`min(tw, buffer_size)` (`native.py:529`), so asking for the full window asks for exactly
`capacity` frames, which the shrunken check rejects. "Give me the whole buffer" would return
an empty array after three retries. A fix that is locally correct can still be wrong one layer
up.

**The cost.** 4096 frames of extra allocation. For a stereo f32 ring that is 32 KB, against
the 115 MB five-minute default ring (`README.md`, `--buffer-minutes`). Every `Ring` pays it,
including each 2-second staging ring a `Mixer` builds per source (`Mixer.zig:24`, `:81`).
Zero CPU cost.

**The consequence you must not forget.** The ring has two sizes with different meanings, and
both are exported (`abi.zig:226-228`, `:241-243`). The header says so at
`core/include/flashback_core.h:40-56`.

### 3.4 Chunked `write`, and why the limit became internal

The guard band's proof needs `b <= M`: every published block at most `max_write_frames`. The
first shape enforced that with an assert on the caller. That would have panicked on real use:
the existing Python suite writes multi-second blocks in one call.

So `write` chunks internally instead:

```zig
var remaining = interleaved;
while (remaining.len > 0) {
    const chunk_frames: u64 = @min(@as(u64, remaining.len / self.channels), max_write_frames);
```
`Ring.zig:209`

Callers pass any size. Every individual release-store still advances `total_written` by at most
4096. A normal audio callback (64 to 2048 frames) takes exactly one iteration, so the hot path
is unchanged. A `chunk_frames == 0` early return covers asserts-off builds (`Ring.zig:212-219`).

`max_write_frames` was demoted from a `Config` field to a file-level constant at the same time
(`Ring.zig:50-57`). With chunking it is the ring's own publish granularity, not something a
caller varies.

RT-safety survives: no lock, no allocation, no error path (`Ring.zig:188-195`). The one
addition is the deferred flush drained at the top of `write` (`Ring.zig:202`), which is a
bounded memset, still lock-free and allocation-free.

### 3.5 Generation tags in `Summary`, and the seqlock over them

Each slot stores the absolute frame index of its first frame as a tag (`Summary.zig:24`).

```zig
const fresh = self.slot_abs[slot_idx] != slot_start_abs;
if (fresh) {
    self.slot_abs[slot_idx] = slot_start_abs;
    self.count[slot_idx] = 0;
```
`Summary.zig:124`

Tag matches: accumulate. Tag differs: this slot belongs to an older lap, so overwrite. One
comparison replaces any clearing pass on wrap.

`flush` then has a problem. It resets `total_written` to 0, so absolute indices restart. A slot
still carrying its stale pre-flush tag can match a new write's recomputed tag, same number,
different epoch, and take the accumulate branch. Pre-flush and post-flush audio merge into one
slot's statistics.

The fix is one memset, `poison`, writing `-1` into every tag (`Summary.zig:69-82`). `-1` is
not a valid absolute index, so no incoming span can match it. That is why `slot_abs` is
`[]i64` and not `[]u64`: the sentinel needs a value outside the domain. `init` calls `poison`,
so a fresh `Summary` sits at generation 2 (`Summary.zig:52`, test `:347-349`).

The cost is O(n_slots), not O(frames). At 300 seconds with 4096-frame slots that is about
3,500 slots, versus 14.4 million frames. With a writer registered, `poison` runs on the writer
thread inside the deferred flush (`Ring.zig:156`, `:181-186`); it is bounded and never blocks.

**The seqlock.** The audio thread writes slots while the UI thread reads them. Issue #23 was
the version with no synchronization at all. Now `update` and `poison` bump `gen` to odd
before touching a slot and to even after (`Summary.zig:79-80`, `:113-114`), and every reader
goes through `seqRead`: read the generation, run the read, read it again, retry on a mismatch,
four attempts (`Summary.zig:148-159`). The contract is best effort and says so: after four
torn attempts the last result is returned anyway, because a stats bin is display data
(`Summary.zig:167-190`). `rmsBins` is the caller (`Summary.zig:199-217`, `:219-265`).

The test that pins poisoning is worth reading (`Ring.zig:1103-1128`): it writes `1,1,1,1`,
flushes, writes `3,3`, and asserts RMS 3.0. Without poisoning the answer is
`sqrt(22/6)`, about 1.915. That number is the whole point of the test.

### 3.6 32767 versus 32768

```zig
const v: i16 = @intFromFloat(std.math.clamp(@round(clamped * 32767.0), -32768.0, 32767.0));
```
`wav.zig:348`

**Decision.** Encode by 32767, so `round(1.0 * scale)` stays in range without clamping. The
positive and negative rails are then symmetric at plus or minus 32767, and `-1.0` lands one
LSB short of the type's floor (`wav.zig:319-324`).

**The reader divides by 32768** (`wav.zig:254-257`, `:264`, `:271`), the libsndfile
convention, so a full-scale file from another encoder decodes to exactly 1.0. The pair is not
a bit-exact identity for PCM and does not claim to be; the round-trip test pins what it is
(`wav.zig:853-883`), and `tests/unit/test_native_smoke.py:161-175` pins the quantizer against
`round(x * scale) / denom` from the Python side. FLOAT32 is the bit-exact path, and it is what
the scratch files use (decision 0007).

Above full scale this encoder clamps (`wav.zig:339`, `:355`). Note also `wav.zig:326-329`:
NaN silently becomes full-scale positive, because `@min`/`@max` return the non-NaN operand and
`clamp`'s bounds are finite. NaN reads as loud, not as silence. This was verified empirically
on the pinned toolchain after an analytical prediction that it would trap turned out to be
wrong.

### 3.7 Serializing file writes

```zig
pub const io = std.Io.Threaded.global_single_threaded.io();
...
pub var write_mutex: std.Io.Mutex = .init;
```
`wav.zig:93`, `wav.zig:103`

`wav.writeFile` reaches for `std.Io.Threaded.global_single_threaded`, the singleton std
reserves for "hardcode a synchronous Io" (`wav.zig:505-527`). Std documents that singleton as
not supporting concurrency. The caveat was traced to async and task-group paths that
`writeFile` never uses, but not every syscall wrapper was traced.

**Decision.** Do not resolve the question; make it moot. Every writer takes `write_mutex` for
the call's duration: `fb_wav_write` (`abi.zig:317-318`), `fb_checkout_export`
(`abi.zig:894-895`), the scratch worker's write and its rename (`Scratch.zig:214-218`,
`:193-200`). None of them is the audio thread, so a lock costs nothing that matters. Readers
take no lock, because `open` and `readPositionalAll` discard the `Threaded` state
(`wav.zig:89-92`).

The mutex lives in `wav.zig`, not `abi.zig`, because `Scratch.zig` must lock it and must not
import `abi` (`wav.zig:100-102`; `abi.zig:37`).

**One rule follows.** Never wait for a scratch job while holding `write_mutex`: the worker
takes the same mutex to finish the job, so the wait would deadlock. `fb_checkout_export` waits
first, then locks (`abi.zig:889-893`).

Two Zig 0.16 details. There is no bare `std.Thread.Mutex` anymore; blocking primitives moved
under `std.Io`, which is why the mutex needs an `Io` value to block on. `lockUncancelable` is
used rather than `lock` because this `Io` has no cancelation source and an `export fn` has no
error path to plumb one through (`abi.zig:317`; `Scratch.zig:34-37`). The same move took
`std.Thread.sleep`: threads sleep through `std.Io.sleep` (`Capture.zig:19-22`,
`Mixer.zig:30-35`).

There are two mutexes in the library now: this one and `Scratch.mutex`, with its condition
variable (`Scratch.zig:50-51`; section 3.13). `Ring.write` is untouched by both
(`Ring.zig:188`). A test pins that `std.Io.Mutex` is real cross-thread exclusion, after a
review doubted it (`Scratch.zig:1034-1092`).

### 3.8 Two sizes at the Python boundary

The guard band forced a decision on the host side. From `native.py:11-19`:

```
TWO SIZES, not one: fb_ring_capacity() is the READABLE window ...
fb_ring_storage_frames() is the PHYSICAL frame count backing
fb_ring_storage
```

Concretely:

- `buffer_size = fb_ring_capacity(...)` (`native.py:433`): every "how much audio can I get
  back" clamp.
- `self.buffer = np.ctypeslib.as_array(storage, shape=(storage_frames, channels))`
  (`native.py:437-444`): the zero-copy view's shape, kept for tests only.
- `write_pos = total_written % self._storage_frames` (`native.py:458-463`): the physical
  position.

The display no longer walks the view: peak bins and RMS are read in Zig
(`fb_ring_peak_bins`, `fb_ring_rms`, `abi.zig:284-298`), so a wrong size on the host side now
breaks tests rather than the waveform. The rule still binds `write_pos`.

### 3.9 Capture: one thread, one ring, one owner of the writer flag

`Capture.zig` is one capture source: a Zig-owned thread pulls packets from a
`Backend.Stream` and writes them into a `Ring` (`Capture.zig:1-4`). The struct owns a
`*Ring`, a `Backend.Backend` vtable, the spec fields, a fixed 256-byte device-id buffer copied
at `init` because the caller's ctypes string dies before the thread reads it
(`Capture.zig:16`, `:24-31`, `:62-67`), an optional `std.Thread` (`:32`), atomics for stop,
running, done, frames written, xruns and mix rate (`:33-42`), and an `ErrorSlot` (`:43`).

**Thread ownership.** `start` runs on the control thread. It stores `ring.writer_active` true
before `std.Thread.spawn`, and an `errdefer` clears it if the spawn fails (`Capture.zig:77-97`).
`stop` stores the stop flag, joins, clears the flag, then drains a deferred flush on the
control thread, which is now the only thread touching the ring (`:99-110`). The worker runs
`runStream` and then `idleUntilStopped` (`:131-135`): a worker that lost its stream still owns
the writer registration, so it keeps draining flushes every 10 ms until `stop`
(`:137-147`). Without that, a source that died on open left the flag true with no drainer, and
a user's flush became a silent no-op (decision 0006).

**RT rules.** The loop never locks, allocates, or fails (`Capture.zig:1-4`). It drains a
pending flush at the loop top before `stream.next`, so a silent source cannot starve a flush
(`:159-165`). Packet bytes go straight to `ring.write` (`:172`); a `discontinuity` flag counts
an xrun (`:171`). `Stats` is an extern struct with a `sources` bitmask so a mixer can report
which source died (`:12-15`).

ABI: `FbCaptureSpec` (`abi.zig:503`), `specFromAbi` (`:568-578`), `fb_capture_create`
(`:580-586`), `fb_capture_start` (`:588-594`), `fb_capture_stop` (`:596-598`),
`fb_capture_destroy` (`:600-603`), `fb_capture_stats` (`:605-607`),
`fb_capture_last_error` (`:609-611`). `fb_devices_list` (`:554-558`) and `fb_processes_list`
(`:562-566`) sit beside them.

Zig concepts here: `std.Thread.spawn(.{}, run, .{self})` takes its arguments as a tuple
(`Capture.zig:95-96`); `@errorName` into a fixed buffer (`:151`, `:167`); `?std.Thread` with
`orelse return` (`:100`); a `defer` chain in `runStream` that reads bottom-up, stop then
deinit then running-false (`:156-158`).

### 3.10 Peak bins: one reducer, three storages

`peaks.zig` is one min/max reducer with one bin-edge rule for three callers: the live ring, a
checkout's RAM copy, a scratch file (`peaks.zig:1-6`). `PeakBin` is an extern pair of f32
(`:13`), layout pinned by `@sizeOf` and `@offsetOf` (`abi.zig:1345-1348`). `binEdge`
reproduces `numpy.linspace`'s integer cast, `trunc(float(i) * step)`, with the last edge
exactly `n`; the multiply order is load-bearing by one frame, and a test named case G pins the
one input where the two orders differ (`peaks.zig:66-74`, `:15-22`). `reduceFrame` seeds min
and max from the first frame rather than from zero (`:76-90`). `peakBinsFlat` copies a
predecessor into an empty bin and leaves an empty bin 0 at zero (`:92-116`). `peakBinsFile`
streams 64 KiB chunks, advances the bin with the frame counter, and fills empty bins in a
final pass; the parity tests prove it equals the flat reducer bit for bit (`:118-166`,
`:168-212`).

`Ring.peakBins` reads the ring in place through the seqlock, never copying a
multi-hundred-megabyte ring at 30 Hz (`Ring.zig:369-395`). It leaves 4096 frames of headroom
below capacity on a saturated ring and stride-samples above 256 samples per bin on an absolute
grid, so a rolling window does not re-pick samples (`:357-367`, `:404-416`). Its verify bounds
only the old end of the span, so the stride branch may read a few frames into the writer's
in-flight block; the result is display-only by construction (`:383-395`, `:448-455`).
`Ring.rmsLatest` reads through `read` in 4096-frame chunks with a 32 KiB stack scratch and
sums squares in f64 (`:469-494`).

`@min` and `@max` ignore NaN, unlike numpy (`Ring.zig:380-381`). The Python host maps the
output as `float32[n_bins][channels][2]` (`peaks.zig:11-12`; `native.py:396`).

ABI: `fb_ring_peak_bins` (`abi.zig:284-290`), `fb_ring_rms` (`:292-298`),
`fb_wav_peak_bins` (`:367-375`), `fb_checkout_peak_bins` (`:849-858`).

### 3.11 Mixer: N stages, one publish per tick

`Mixer.zig` sums N captures into one target `Ring` on a Zig-owned mixer thread; each source
is a `Capture` writing a 2-second staging `Ring` (`Mixer.zig:1-5`, `:23-28`). The struct is
self-referential, each `Capture` points at its staging ring inside `sources`, so `init` takes
`*Mixer` and the struct must never move; the ABI allocates it first and initialises in place
(`Mixer.zig:11-14`, `:53`, `:61-74`; `abi.zig:620-627`). Allocation happens in `init` only;
the loop works in two fixed arrays sized `max_write_frames * 2` (`Mixer.zig:7-9`, `:41-45`).

`init` rejects zero or more than 8 sources and any spec whose rate or channels differ from the
target, because nothing resamples (`Mixer.zig:54-60`). It unwinds with an `errdefer` over a
progress counter so only built stages are freed (`:76-78`). `start` stores the target's
`writer_active` before any thread exists, then starts each capture with a second progress
counter; LIFO order stops captures first, then clears the flag (`:96-120`). `stop` joins,
stops captures, clears the flag, drains (`:122-132`).

**The tick.** Drain a deferred flush, sleep 10 ms, compute the common span every live stage
holds, capped at one publish (`Mixer.zig:175-216`). A stage that lapped the cursor resumes
`lapMargin` frames inside the window and charges one xrun (`:197-207`, `:241-249`; issue
#46). A source whose worker is `done` with nothing staged leaves the span so the others carry
on (`:208-212`; issue #47). Each stage is read through the seqlock; a torn read gives up the
tick (`:220-231`). The sum is clipped to [-1, 1] and written once (`:232-233`).

`stats` sums xruns with a saturating add, sets one bit per running source, and reports the
first published mix rate (`Mixer.zig:134-154`). `lastError` returns its own message, else the
first source's (`:161-169`).

ABI: `fb_mixer_create` (`abi.zig:613-628`), `fb_mixer_start` (`:630-636`), `fb_mixer_stop`
(`:638-640`), `fb_mixer_destroy` (`:642-645`), `fb_mixer_stats` (`:647-649`),
`fb_mixer_last_error` (`:651-653`).

Zig concepts here: in-place init of a self-referential struct; the saturating operators `-|`
and `+|=` (`Mixer.zig:196`, `:143`); `inline fn bit` (`:156-159`); `@popCount` in a test
(`:511`). The `FakeBackend` `children` router hands each capture thread its own packet script
in arrival order (`FakeBackend.zig:48-53`; `Mixer.zig:302-305`).

### 3.12 Playback: a render thread and a two-flag handshake

`Playback.zig` is one clip player: a Zig-owned render thread feeds a `Backend.RenderStream`
from an owned copy of the clip (`Playback.zig:1-6`). The clip is allocated only in `bind`, on
the control thread; a two-flag handshake, `playing` and `in_copy`, keeps `bind` from freeing a
buffer the thread is copying from (`:4-6`, `:129-137`). The largest single write is 8192
frames; the scratch is a fixed array in the struct (`:18-21`, `:40`).

`ClipSource` is a tagged union: `frames` is copied, `file` is read straight into the new
buffer through `wav.zig` (`Playback.zig:86-93`, `:115-128`). `bind` validates channels and
rate first, computes `n_frames * channels` with `std.math.mul`, allocates with `errdefer`,
fills, then swaps under the handshake; a failed bind keeps the old clip (`:95-147`). A rate or
channel change sets `reopen`; the thread reopens on its own thread because the COM apartment
belongs to the thread that opened the stream (`:140-146`, `:281-298`). `play` joins a thread
that exited on error so the next play retries the open (`:149-171`). `seek` clamps to
`clip_frames` (`:177-179`).

`fill` raises `in_copy`, reads `playing`, bounds the read by the open stream's channel count
rather than `clip_frames`, and leaves the cursor alone when a seek sits past a stale stream's
bound (`Playback.zig:210-247`). `run` owns an optional stream, publishes the mix rate before
running, and uses one `defer` block to leave `playing` false and `done` true on every exit
(`:249-312`). Any early return from the loop still owns its registrations until the control
thread's `stop`, the same rule `Capture` follows. The wait is event-driven: WASAPI signals once
per period, so the thread sleeps at zero CPU between fills (`Backend.zig:46-48`).

ABI: `fb_playback_create` (`abi.zig:659-665`), `fb_playback_bind` (`:667-676`),
`fb_playback_play` (`:678-681`), `fb_playback_pause` (`:683-685`), `fb_playback_seek`
(`:687-689`), `fb_playback_set_device` (`:691-693`), `fb_playback_state` (`:695-697`),
`fb_playback_last_error` (`:699-701`), `fb_playback_destroy` (`:703-706`),
`fb_playback_bind_checkout` (`:927-934`). `Playback.State` is extern (`Playback.zig:15`).

Zig concepts here: `union(enum)` with payload capture in `switch` (`Playback.zig:90-93`,
`:108-111`); `?Backend.RenderStream` unwrapped with `if (stream) |s|` inside a `defer`
(`:258-279`); `anytype` context typed by `@TypeOf(ctx)` for test predicates (`:50-54`).

### 3.13 Scratch: one writer thread, an intrusive FIFO, an LRU with no heap

`Scratch.zig` is the scratch writer thread and the RAM cache, one per process
(`Scratch.zig:1-5`; decision 0009). Two job kinds ride one intrusive FIFO: `.write` streams a
checkout's RAM copy to `<path>.part` then renames it; `.load` reads an evicted checkout back
(`:2-5`, `:169-212`). The same struct holds the LRU byte cache (`:54-57`). No heap for queue
or LRU bookkeeping: the links live inside `Checkout` (`queue_next`, `lru_prev`, `lru_next`,
`Checkout.zig:52-54`); only a `.load` allocates, and only its clip (`Scratch.zig:12-16`).

**Thread rules.** `mutex` guards the FIFO links, the LRU links, `resident_bytes`,
`budget_bytes`, and every `job`, `pinned` and `frames` access on the control thread
(`Scratch.zig:7-9`). The worker never holds `mutex` during file I/O (`:10-11`, `:138-167`).
One control thread is assumed; `thread` itself has no lock (`:18-23`). `write_state` is the
one atomic the ABI polls without the lock (`Checkout.zig:9-13`, `:44`).

`start` spawns; `stop` sets the flag, broadcasts, joins, and the worker drains every queued
job before exiting, so a quit never leaves a `.part` (`Scratch.zig:66-84`, `:144-148`).
`submitLocked` links at the FIFO tail and, for a `.write`, inserts at the LRU head once
(`:95-107`). `waitLoad` waits only on `.load`, `waitJob` on any job; both return early with no
worker running, which means no quiescence, so `forget` must dequeue by hand in that case
(`:109-136`, `:312-333`, `:341-365`). That early-out is a trap: a wait that returns at once is
not a wait that succeeded. `lru_bytes` snapshots the resident size at insert so removal
subtracts exactly what was added; sampling `residentBytes()` twice would underflow
(`:226-254`; `Checkout.zig:55-61`). Eviction walks from the tail while over budget and skips
pinned, held, in-flight and not-yet-written entries (`:367-394`). `hold` and `release` give an
ABI read transient residency; `touch` records a use (`:270-303`).

ABI: `fb_scratch_create` (`abi.zig:726-734`), `fb_scratch_start` (`:736-739`),
`fb_scratch_stop` (`:741-743`), `fb_scratch_destroy` (`:745-750`), `fb_scratch_set_budget`
(`:752-754`), `fb_scratch_resident_bytes` (`:756-758`). Every checkout export brackets its
read with `hold`, `release` and `touch` (`:849-858`, `:881-911`, `:927-934`);
`fb_checkout_info` needs both `waitLoad` and the mutex, neither alone (`:808-838`).

Zig concepts here: an intrusive singly linked FIFO and a doubly linked LRU with no allocator
(`Scratch.zig:52-55`, `:98-100`, `:226-254`); `std.Io.Mutex` and `std.Io.Condition` with
`lockUncancelable` and `waitUncancelable`, both taking the `Io` (`:34-37`, `:50-51`, `:122`,
`:142`); a function-pointer seam, `*const fn (...) anyerror!void`, so tests inject a parked or
failing writer (`:45-47`, `:60`, `:407-429`); `unreachable` for a state the code proves
impossible (`:158`); the `@min` subtraction guard on a running total (`:246-253`).

### 3.14 Checkout: one RAM copy, one file range

`Checkout.zig` is one checkout: the one RAM copy of its frames, or none once evicted, plus
where the same audio lives on disk as `(path, start_frame, n_frames)` (`Checkout.zig:1-7`). A
root created from the ring owns its file at `(0, all)`; a slice references its parent's file;
an adopted checkout may start anywhere in a file it does not own (`:3-6`). `start_frame` is
absolute into the file, never parent-relative, so nested slices stay absolute (`:36-40`).
`WriteState` is `enum(u8)` because the Python host reads the wire value (`:23-25`; test
`abi.zig:936-942`). `max_path` is 1024 (`:28`).

`create` is the one constructor: it rejects a path at or past `max_path` and `channels == 0`,
so every later divide by channels is safe (`Checkout.zig:63-90`). `createFromRing` guards
`n * chans` in divide form, allocates once with `errdefer`, and reads the ring in
`max_write_frames` pieces so a torn piece retries the piece (`:100-125`). `slice` uses the
subtraction-form guard and `std.math.add` against a corrupt parent offset (`:133-146`).
`load` checks the file's channel count against the checkout's before allocating
(`:153-176`). `evict` frees the copy; the file keeps the audio (`:178-185`). `peakBins` serves
from RAM or streams the file with the same reducer (`:187-204`). `source` returns a
`Playback.ClipSource`, a sub-slice or a file range (`:206-217`).

Concurrency: `write_state` is atomic; `job`, `pinned`, `hold`, the links and `frames` belong
to `Scratch.mutex`; nothing in this file locks (`Checkout.zig:9-13`).

ABI: `FbCheckoutInfo` (`abi.zig:710-714`; layout test `:1366-1381`), `checkoutStatus`
(`:716-724`), `fb_checkout_create` (`:760-769`), `fb_checkout_slice` (`:771-781`),
`fb_checkout_open` (`:783-806`), `fb_checkout_info` (`:826-838`), `fb_checkout_peak_bins`
(`:849-858`), `fb_checkout_pin` (`:860-862`), `fb_checkout_export` (`:868-911`),
`fb_checkout_destroy` (`:913-920`), `fb_playback_bind_checkout` (`:922-934`).

Zig concepts here: `?[]f32`, an optional slice, unwrapped with `if (self.frames) |f|`
(`Checkout.zig:96-98`, `:148-150`, `:180-185`, `:211-215`); `std.atomic.Value(WriteState)`
over an enum (`:44`); `std.math.mul`, `std.math.add` and divide-form guards so hostile ctypes
values return a status instead of trapping (`:113`, `:139-144`, `:163`); a fixed path buffer
instead of an allocated string (`:34-35`, `:88-94`).

### 3.15 The WAV reader and markers

`wav.open` walks the RIFF chunks to `data` with positional reads, skipping unknown chunks and
honouring the word-alignment pad byte (`wav.zig:125-169`). `parseFmt` handles plain and
EXTENSIBLE fmt bodies, takes the real tag from the SubFormat GUID, accepts float32, pcm_16 and
pcm_24 only, and rejects a channel count above `max_channels` or a `block_align` that
disagrees (`wav.zig:171-203`). `frames` is clamped to what the file holds, so a
crash-truncated `.part` reads its true prefix (`:105-108`, `:157-164`).

`readFrames` uses the subtraction-form range guard (`start > frames or n > frames - start`) so
a hostile start cannot overflow-trap, streams through a 64 KiB stack buffer, and treats a
short read as `OutOfRange` (`wav.zig:226-252`). `decodeSamples` divides PCM codes by
`2^(bits-1)` and sign-extends 24-bit by shifting into the top of an `i32` (`:254-274`).
`read_chunk_bytes` and `max_channels` are shared constants with their bounds derived in
comments (`:205-218`); `max_channels` is what keeps `writeHeader`'s `block_align` cast in
range, and `writeHeader` returns `error.TooLong` through `std.math.mul` instead of trapping on
a payload past 4 GiB (`:289-294`).

`Markers` writes `cue ` (two points), `smpl` (one loop, inclusive end), and `LIST/adtl`
labels after `data`, 186 bytes, validated against the exported file's frame count and against
`u32` (`wav.zig:370-440`). `copyRange` streams a sub-span into a new file in any subtype,
validates before creating the destination, re-patches the RIFF size to cover the pad byte and
the markers, and pads an odd data chunk (`:442-498`). Serialisation is the caller's job
through `write_mutex` (section 3.7). The drag-out design that needs the markers is decision
0008.

ABI: `FbWavInfo` (`abi.zig:326-328`), `wavStatus` (`:330-336`), `fb_wav_info` (`:338-343`),
`fb_wav_read` with the `out_len` echo (`:345-360`), `fb_wav_peak_bins` (`:362-375`),
`FbMarkers` (`:864-866`), markers through `fb_checkout_export` (`:876-911`).

Zig concepts here: positional file I/O taking an explicit `Io` (`wav.zig:131`, `:141`,
`:242`); a struct with a method computing block align (`:109-119`); `inline for` over the
subtypes in a test (`:859`); hand-built byte images as test fixtures (`:685-742`).

### 3.16 The backend interface and its three implementations

`Backend.zig` is the interface: `*anyopaque` plus a vtable of function pointers, the std idiom
of `std.mem.Allocator` and `std.Io`, so `Capture` never learns which backend it runs on
(`Backend.zig:1-6`; decision 0005). `Kind` is `enum(u8)` with loopback, input, process,
render (`:8`). `Error` is a closed set (`:10`). `Device` is extern so the ABI passes it
through (`:12-13`). `Stream` wraps `next(timeout)`, `stop`, `deinit`, `mixRate` (`:19-44`);
`RenderStream` adds the event-driven `wait`, `available`, `write` (`:46-83`); `Backend` has
`enumerate`, `open`, `openRender` (`:85-109`). `open` is called on the capture thread and
starts the stream (`:92-93`).

`FakeBackend.zig` is the test double, kept in `src/` so `Capture`'s tests can import it;
`root.zig` analyzes it and `abi.zig` never references it, so nothing is exported
(`FakeBackend.zig:1-5`). Scripted packets, injectable open and stream errors, a discontinuity
index, the `Hold` union that parks the worker (`:10-24`, `:46-47`, `:60-66`, `:91`,
`:101-118`), a `children` router for multi-source owners (`:48-53`, `:85-88`), and a render
sink that records every write (`:26-43`, `:139-183`).

`WasapiBackend.zig` implements capture, per-process loopback, render and enumeration over
hand-written COM (`WasapiBackend.zig:1-8`). Capture polls at 10 ms against a 200 ms buffer
because event-driven loopback has a known quirk; render is event-driven (`:1-8`, `:25-27`).
Streams come from fixed pools, no allocator on the audio path, claimed by compare-and-swap
because `Mixer.start` and `Playback` each spawn openers (`:46-62`, `:64-79`, `:101-116`). A
format candidate chain serves the process-loopback client, which has no device to query
(`:29-44`). `RoInitialize` rather than `CoInitializeEx`, because process loopback needs it
(`:217-220`, `:268-274`). `enumerateProcesses` walks Toolhelp32 (`:375-396`).

`wasapi.zig` declares the COM interfaces by hand: a COM interface is a pointer to a vtable
struct with `extern struct` layout and `callconv(.winapi)`; method order is the binary
interface (`wasapi.zig:1-6`). `ole32` is linked through `build.zig`; `combase.dll`'s
`RoInitialize` is resolved at runtime with `LoadLibraryW` and `GetProcAddress`, because Zig
ships no import library for it (`wasapi.zig:84-138`; `build.zig:13-22`).

`ErrorSlot.zig` is the fixed 256-byte error slot shared by `Capture`, `Mixer` and
`Playback`: the worker writes at most once per run, the control thread reads at any time
(`ErrorSlot.zig:1-3`, `:7`). `set` uses `bufPrintZ` and restores the sentinel on overflow
(`:20-28`); `last` returns `[:0]const u8`, and its `n == 0` guard is load-bearing, because
`err_buf[0..n :0]` reads `err_buf[n]` and at `n == 0` that races the writer's first byte
(`:30-39`; issue #45).

`convert.zig` converts one WASAPI packet to interleaved f32 at the requested channel count
with no OS calls (`convert.zig:1-3`, `:60-89`).

`mem.zig` is the physical memory query for the host's footprint check: total RAM and free
RAM, 0 where the platform cannot say; allocation-free, no state, safe from any thread
(`mem.zig:1-5`; decision 0010). `Info` is an extern struct mirrored by `FbMemInfo`
(`:9-10`; layout test `:78-81`). `query` switches on `builtin.os.tag` at compile time:
`GlobalMemoryStatusEx` on Windows through a hand-declared `extern "kernel32"` with
`callconv(.winapi)` (`:20-47`), `sysinfo(2)` on Linux with `freeram + bufferram`
(`:49-61`), `std.process.totalSystemMemory` elsewhere (`:16`). The Win32 versioning idiom,
`dwLength` set to `@sizeOf` on entry, is pinned at 64 bytes (`:22-23`, `:44`, `:74-76`).
ABI: `fb_mem_info` (`abi.zig:207-211`).

Zig concepts here: `*anyopaque` plus vtable (`Backend.zig:19-22`, `:85-88`);
`@ptrCast(@alignCast(ptr))` to recover the concrete type (`WasapiBackend.zig:203`);
`extern struct` vtables with `callconv(.winapi)` (`wasapi.zig:1-6`); runtime symbol
resolution (`wasapi.zig:124-138`); `extern "kernel32" fn ... callconv(.winapi)` (`mem.zig:40`)
with `@sizeOf` handed to the OS as a runtime value (`:44`).

## 4. Patterns and anti-patterns actually present

### Patterns worth keeping

- **The ABI shim holds little logic.** Most `export fn`s in `abi.zig` are a type conversion
  plus a call. Validation guards exist because C callers are untrusted; the `hold`, `release`
  and `touch` brackets around checkout reads exist because the cache can evict under a reader
  (`abi.zig:853-855`, `:886-888`, `:929-931`). Anything more belongs in the module.
- **One source of truth for shared constants.** `Summary.max_bins` (`Summary.zig:84-90`) sizes
  the scratch arrays and backs the ABI's rejection (`abi.zig:274-282`). `wav.max_channels` is
  shared by `parseFmt` and `fb_wav_write` (`wav.zig:209-218`, `:195`; `abi.zig:308`).
  `Mixer.max_sources` by `init` and `fb_mixer_create` (`Mixer.zig:23`, `:54`; `abi.zig:614`).
  Each was a duplicated literal until review caught it.
- **Comments that carry rejected alternatives and their measurements.** `Ring.zig:647-738`
  records two failed test geometries with their numbers and an explicit "Do not re-run this
  experiment" (`:726`). That is expensive knowledge stored where it will be read.
- **Tests that name the mutation they survive.** `Ring.zig:605-618` explains why
  `abs_start=100` and not `abs_start=0`: at 0 the test passes whether or not the code under
  test exists.
- **Overflow guards in subtraction form.** `start > frames or n > frames - start` cannot
  overflow; `start + n > frames` can, and in ReleaseSafe an overflow is a trap, not a wrong
  answer (`wav.zig:226-252`, `Checkout.zig:139-144`).

### Closed since phase 1

The compromises the first version of this document listed are all closed.

- **#20, `flush` versus the writer.** Closed by writer ownership: `writer_active` and
  `flush_pending` (`Ring.zig:35-36`, `:131-137`, `:161-186`); tests `Ring.zig:1130-1153`,
  `Capture.zig:304-394`, `Mixer.zig:376-413`. Decision 0006.
- **#21, `Ring.init` did not validate.** The five-clause guard moved into `Ring.init` itself
  and returns `error.InvalidArgument` (`Ring.zig:60-64`; tests `:496-509`). `fb_ring_create`
  passes it through (`abi.zig:173-205`). A direct Zig host gets the same protection as the ABI.
- **#23, `Summary.rmsBins` raced `update`.** Closed by the generation seqlock (section 3.5).
- **#26, ctypes GIL tail latency.** Closed by moving capture into Zig: no ctypes call per
  packet (`Capture.zig:159-175`). No production Python write path remains (decision 0002).
- **The hidden two-channel ceiling.** `Ring.init` rejects `channels > 2` (`Ring.zig:63-64`;
  test `:502-504`). The `Summary` assert is still there (`Summary.zig:241`) and
  `Ring.rmsLatest` relies on the same bound (`Ring.zig:481-482`); they are now unreachable
  from any constructor.
- **Unchecked narrowing casts in `writeHeader`.** `std.math.mul` and `error.TooLong`
  (`wav.zig:289-294`; tests `:34-51`), mapped to `invalid_arg` at the ABI (`abi.zig:320`).

### Things worth knowing, still not tracked

- **96 KiB of stack scratch on a caller-supplied thread.** `Summary.rmsBins` sizes its bins to
  the maximum regardless of the requested `n_bins` (`Summary.zig:242-243`, documented at
  `:192-198`). Right for CPython's 8 MB thread stacks; worth knowing before a host with small
  stacks calls it. The other large scratches live inside their structs, not on the stack
  (`Mixer.zig:44-45`, `Playback.zig:40`); the WAV paths put 64 KiB on the stack
  (`wav.zig:236`, `:478-479`, `:536`; `peaks.zig:134`); `Ring.rmsLatest` 32 KiB
  (`Ring.zig:482`).
- **A merged error case.** `Ring.read` returns `error.Overwritten` after three failed attempts
  (`Ring.zig:348`) whether the cause was a genuine lap or a racing flush; `peakBins` does the
  same (`:457-458`). `native.py:515-523` then maps every error to an empty array. Callers
  cannot distinguish "your data is gone" from "try again". Small, and a real loss of
  information.
- **Deliberate dead code, kept and documented.** The outer clamps in `encodeSamples`
  (`wav.zig:348`, `:359`) have unreachable lower rails; the inner clamp already bounds the
  input to plus or minus 1.0. The mutation does not redden any test (`:665-683`). Kept as a
  defensive guard at an ABI-adjacent boundary, with the rationale inline (`:340-347`,
  `:355-358`). It will look like a bug on first read, and it is not.
- **`Summary.seqRead` is best effort.** After four torn attempts it returns the last read
  (`Summary.zig:167-190`). A stats bin can be wrong for one frame. Documented, and right for
  display data.

## 5. Traps this codebase paid for

**Tests that pass without running.** Adding `pub const Ring = @import("Ring.zig");` to
`root.zig` did not make `Ring.zig`'s tests run. `zig build test` reported success while
executing zero of them. `std.testing.refAllDecls(@This())` (`root.zig:49-51`) is what pulls
them in, and it is not recursive. The rule that came out of it: after adding tests, check that
the test count rose. An exit code proves nothing.

**Mutation checks that do not redden.** The recurring defect of every phase was a test that
looks like it pins something and does not. Concrete cases: a poison assertion that called
`rmsBins(0, ...)`, which short-circuits before ever reading `slot_abs` (`Ring.zig:1094-1100`
now checks the field directly); a zero-length read test at `abs_start=0`, which passes with the
code under test deleted (`Ring.zig:605-618` now uses `abs_start=100`); a guard with zero
coverage because every test passed valid arguments (`Ring.zig:496-509` now pins each clause);
a boundary test whose 37 bins reached the last bin before the chunk boundary and could not
catch an off-by-one that 300 bins catch (`peaks.zig`); a concurrency test that could pass with
zero contention until a lock-before-submit forced the interleave (`Scratch.zig:1034-1092`).
One more, caught mid-write: proving round-half-away-from-zero with a `@floor` mutation fails,
because `@floor(-16383.5) = -16384`, the same answer. `@trunc` discriminates; the reasoning is
at `wav.zig:564-579`.

The general rule: a compound condition needs one mutation per clause, and the mutation must be
one that should change the answer. A mutation that leaves a local unused is a compile error,
not a red test; add `_ = x;` to observe it.

**A stress test that could not detect what it existed to detect.** The seqlock stress test
(`Ring.zig:647`) reads at `tw - read_frames` with a 512-frame margin, nowhere near the boundary
the guard band protects. Removing the guard band entirely reddened nothing: 0/20 at one
geometry, 0/10 at another. The separate boundary test at `Ring.zig:848` fixed that: 20/20
clean unmutated, 12/20 detecting guard-band removal, with a value signature ("one full lap
ahead") that confirms the failures are genuine (`:903-908`). Getting there took decoupling two
parameters that a previous attempt had tied together: `block_frames = 3968` widens the
writer's unpublished window, `offset = 64` narrows the reader's tolerance (`:914-915`).
Coupling them made the effects cancel. A probabilistic test is not a gate; it is evidence.

**A wait that returns at once is not a wait that succeeded.** `Scratch.waitJob` and
`waitLoad` return early when no worker is running (`Scratch.zig:112-118`, `:127-131`). A
caller that treats that as quiescence frees a job still in the queue. `forget` dequeues by
hand in that case (`:324-333`).

**Defer order, three times.** Section 2.10. The third instance was the one that hung a whole
suite: an unpark that had to be the last registered defer (`abi.zig:1115-1128`).

**Environment-shaped defects invisible on the dev machine.** `zig fmt --check` failed on
Windows CI only, because the repo had no `.gitattributes` and `core.autocrlf` rewrote LF to
CRLF on checkout. The committed bytes were LF the whole time; the fix is the two lines in
`.gitattributes` pinning `*.zig` and `*.zon` to `eol=lf`. Three `wav.zig` tests hardcoded a
temp path that exists only on one workstation and failed on every CI runner; the fix is a
cwd-relative path under `.zig-cache/tmp/` (`wav.zig:602-604`, `test_util.zig:10`). Today CI
runs two jobs, pytest on `windows-latest` and `zig build test` plus `zig fmt --check` on
`ubuntu-latest` (`.github/workflows/test.yml`); the Windows-only files are gated out of the
Ubuntu leg by `root.zig:30-31`, and a test that needs the render backend carries a
Windows-only skip or it fails only in CI.

**Every confident analytical claim about runtime behaviour was wrong, and a measurement
settled it.** The `cap_frames` detection arithmetic (`Ring.zig:699-719`), the NaN-traps-in-
`encodeSamples` claim (`wav.zig:326-329`), and skepticism about `std.Io.Mutex` being real
cross-thread exclusion (`Scratch.zig:1034-1092`). Zero occasions where analysis beat
measurement. For races and language semantics, run it.
